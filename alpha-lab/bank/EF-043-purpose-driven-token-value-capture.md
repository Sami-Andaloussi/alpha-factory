## Mechanism

The value of some tokens depends on their insertion in a real economic loop: users, advertisers,
creators, validators or other actors must have a structural reason to buy, hold, spend or receive
the token. The Basic Attention Token (BAT), a case the library presents, illustrates the idea: it
attempts to tokenise a scarce economic resource, attention, and to organise explicit payment flows
between advertisers, users and publishers. Undervaluation or overvaluation then turns on a decisive
question: does the token really capture part of the value created, or is it only a speculative
wrapper around a service that could work without it?

The same question arises for the utility token in general, which the books define as a fungible
token that is required to use a function of a smart-contract system, or whose value proposition is
directly tied to that function. The economic mechanism is very different from that of a share:
demand comes from the use of the protocol itself, not mainly from a residual claim on flows
distributed by an entity. This can create structural price behaviour when the adoption of the
application grows, when some of the protocol's functions become unavoidable, or when the token
serves as operational collateral. The phenomenon persists as long as the function is truly necessary
and not perfectly substitutable. Many projects have called "utility" tokens whose utility was
economically weak; if the service can be consumed without holding the token, the link between price
and usage falls apart.

The library also notes the mechanism's limits: governance that is sometimes centralised, pre-mined
pools, concentration of supply, adoption bottlenecks, and a dependence on real use rather than on
the narrative.

## Prediction

A token embedded in a real economic loop, with explicit flows between participants who have a
structural reason to buy, hold, spend or receive it, draws its value from the part of the value
created that it really captures; a token that is only a speculative wrapper around a service able to
work without it is overvalued. Structural price behaviour can appear in a utility token when the
adoption of its application grows, when some of the protocol's functions become unavoidable, or when
the token serves as operational collateral, as long as the function is truly necessary and not
perfectly substitutable; it has been observed in DeFi architectures, in the tokens of application
networks and in some utility stablecoins. If the service can be consumed without holding the token,
the link between price and usage falls apart.

## What would refute it

- Tokens with no structural reason to be bought, held, spent or received that hold their value as
  well as tokens embedded in a real economic loop.
- Token values unrelated to the flows of use between participants; utility-token prices that do not
  follow the use of their protocol, even where holding the token is required to use a necessary,
  non-substitutable function.
- Tokens whose service can be consumed without holding them that track the use of their protocol as
  closely as tokens that must be held to use it.
- Tokens that are only wrappers around services able to work without them, valued no lower than
  tokens that capture part of the value created.
